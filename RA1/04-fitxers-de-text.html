1. Les dues APIs per llegir i escriure

Java llegeix i escriu el contingut dels fitxers amb fluxos (streams): canals pels quals les dades circulen en ordre, de l'origen al destí. Hi ha quatre famílies, segons dues preguntes: llegim o escrivim? bytes o caràcters?

LlegirEscriure
Caràcters (fitxers de text)ReaderWriter
Bytes (fitxers binaris)InputStreamOutputStream

Igual que amb la gestió de fitxers, hi ha dues APIs:

  • java.io (clàssica): cal crear i encadenar objectes de fluxos, com FileReader i BufferedReader.
  • NIO.2 (actual): la classe Files ho fa amb un sol mètode.

Nota

En aquest mòdul treballarem amb NIO.2.

2. Llegir

2.1 Tot el fitxer en un String: readString()

Per a fitxers petits, es llegeix tot de cop.

Java Java 
String text = Files.readString(Path.of("notes.txt"), StandardCharsets.UTF_8);  // tot el contingut en un String
System.out.println(text);
System.out.println("Caràcters: " + text.length());

2.2 Totes les línies en una llista: readAllLines()

Per a fitxers petits, es llegeix tot de cop.

Java Java 
List<String> linies = Files.readAllLines(Path.of("notes.txt"), StandardCharsets.UTF_8);  // una posició per línia

for (int i = 0; i < linies.size(); i++) {
    System.out.println((i + 1) + ": " + linies.get(i));   // mostra cada línia numerada
}

2.3 Línia a línia: newBufferedReader()

Només manté a la memòria la línia que s'està processant, i per això serveix per a fitxers de qualsevol mida.

LlegirLinies.java Java 
import java.io.BufferedReader;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;

public class LlegirLinies {
    public static void main(String[] args) {
        Path fitxer = Path.of("notes.txt");

        // newBufferedReader(): obre el fitxer per llegir-lo línia a línia
        try (BufferedReader br = Files.newBufferedReader(fitxer, StandardCharsets.UTF_8)) {
            String linia;
            int num = 0;
            while ((linia = br.readLine()) != null) {   // null: s'ha acabat el fitxer
                num++;
                System.out.println(num + ": " + linia);
            }
        } catch (NoSuchFileException e) {
            System.out.println("No existeix el fitxer: " + e.getFile());
        } catch (IOException e) {
            System.out.println("Error de lectura: " + e.getMessage());
        }
    }   // el try-with-resources tanca el fitxer en sortir del bloc
}

2.4 Filtrar i comptar: Files.lines()

Retorna les línies com un Stream<String>, que es va llegint a mesura que es necessita. És pràctic per filtrar, comptar o transformar.

Java Java 
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.stream.Stream;

public static void main(String[] args) {
    Path fitxer = Path.of("notes.txt");
    // Files.lines(): les línies del fitxer com un Stream (cal tancar-lo amb try-with-resources)
    try (Stream<String> linies = Files.lines(fitxer, StandardCharsets.UTF_8)) {
        long errors = linies.filter(l -> l.contains("ERROR"))   // es queda amb les línies que contenen ERROR
                            .count();                       // i les compta
        System.out.println("Errors: " + errors);
    } catch (IOException ex) {
        System.out.println("Error de lectura: " + ex.getMessage());
    }
}

Fixeu-vos que linies.filter(l -> l.contains("ERROR")).count() equival a escriure això mateix:

Java Java 
long errors = 0;
for (String linia : linies.toList()) {   // toList() converteix l'Stream en una llista
    if (linia.contains("ERROR")) {
        errors++;
    }
}

Per recórrer-lo amb un for-each, primer cal convertir l'Stream en una llista amb toList().

Compte

readString() i readAllLines() carreguen tot el fitxer a la memòria. Amb un fitxer de diversos GB, el programa acaba amb un OutOfMemoryError.

3. La codificació: UTF-8

Un fitxer de text és, en realitat, una seqüència de bytes. La codificació (charset) és la taula que diu quins bytes corresponen a cada caràcter. Si s'escriu amb una codificació i es llegeix amb una altra, els accents surten malament.

Java Java 
Path p = Path.of("salutacio.txt");
Files.writeString(p, "Això és una prova", StandardCharsets.UTF_8);   // escriu el text en UTF-8

String correcte = Files.readString(p, StandardCharsets.UTF_8);       // llegeix en UTF-8
System.out.println(correcte);                                        // Això és una prova

String incorrecte = Files.readString(p, StandardCharsets.ISO_8859_1); // llegeix amb una altra codificació
System.out.println(incorrecte);                                       // AixÃ² Ã©s una prova
CodificacióCaracterístiques
UTF-8L'estàndard actual. Representa qualsevol caràcter: à, ç, €, alfabets no llatins...
ISO-8859-1Codificació antiga d'un byte per caràcter. Té els accents occidentals, però no el símbol €

Des de Java 18, la codificació per defecte és UTF-8 a tots els sistemes operatius. Tot i així, als apunts l'indicarem sempre amb StandardCharsets.UTF_8: així el codi funciona igual amb versions anteriors de Java i queda clar quina codificació es fa servir.

Compte

Si llegeixes amb UTF-8 un fitxer escrit amb una altra codificació, readString() i readAllLines() llancen MalformedInputException (una subclasse d'IOException).

4. Escriure

4.1 Un String sencer: writeString()

Java Java 
Path p = Path.of("salutacio.txt");

// Sense opcions: crea el fitxer, o el buida si ja existia, i hi escriu el text
Files.writeString(p, "Primera línia\n", StandardCharsets.UTF_8);

// APPEND: afegeix el text al final i conserva el que ja hi havia
Files.writeString(p, "Segona línia\n", StandardCharsets.UTF_8, StandardOpenOption.APPEND);

4.2 Una llista de línies: write()

Java Java 
List<String> ciutats = List.of("Barcelona", "Girona", "Lleida", "Tarragona");

// write(): escriu cada element de la llista en una línia (afegeix el salt de línia)
Files.write(Path.of("ciutats.txt"), ciutats, StandardCharsets.UTF_8);

4.3 Línia a línia: newBufferedWriter()

Per quan les dades es generen a poc a poc o són moltes.

Java Java 
// newBufferedWriter(): obre el fitxer per escriure-hi a poc a poc
try (BufferedWriter bw = Files.newBufferedWriter(Path.of("taula.txt"), StandardCharsets.UTF_8)) {
    for (int i = 1; i <= 10; i++) {
        bw.write("7 x " + i + " = " + (7 * i));   // escriu el text (sense salt de línia)
        bw.newLine();                             // afegeix el salt de línia del sistema operatiu
    }
}   // en tancar-se, el buffer es buida al disc

Compte

BufferedWriter guarda el text en un buffer (memòria intermèdia) i l'escriu al disc per blocs. Si no el tanques, el fitxer pot quedar buit o incomplet. Obre'l sempre amb try-with-resources.

4.4 Sobreescriure o afegir: StandardOpenOption

Els mètodes d'escriptura accepten opcions al final que indiquen com s'obre el fitxer.

OpcióComportament
CREATECrea el fitxer si no existeix
CREATE_NEWCrea el fitxer; si ja existeix, llança FileAlreadyExistsException
TRUNCATE_EXISTINGBuida el contingut abans d'escriure (sobreescriure)
APPENDEscriu al final i conserva el contingut anterior (afegir)
Java Java 
Path log = Path.of("app.log");

// Afegir al final; si el fitxer no existeix, el crea
Files.writeString(log, "nova entrada\n", StandardCharsets.UTF_8,
                  StandardOpenOption.CREATE, StandardOpenOption.APPEND);

// Només si el fitxer no existeix: així no esborrem mai res
Files.writeString(Path.of("config.txt"), "idioma=ca\n", StandardCharsets.UTF_8,
                  StandardOpenOption.CREATE_NEW);

Recorda

Si no poses cap opció, el mètode fa servir CREATE i TRUNCATE_EXISTING: crea el fitxer si no existeix i, si existeix, en substitueix el contingut.

5. CRUD sobre un fitxer de text amb BufferedReader/Writer

CRUD són les quatre operacions bàsiques sobre dades: Create (afegir), Read (consultar), Update (modificar) i Delete (esborrar). Amb un fitxer de text, les dues primeres ja les saps fer. Les altres dues tenen una limitació: no es pot canviar ni esborrar una línia directament dins del fitxer.

OperacióCom es fa en un fitxer de text
AfegirEscriure al final amb APPEND, sense tocar la resta
ConsultarLlegir les línies amb BufferedReader
ModificarLlegir-ho tot, canviar la línia a la memòria i reescriure el fitxer
EsborrarLlegir-ho tot, treure la línia de la memòria i reescriure el fitxer

Exemple: una llista de tasques, una per línia.

GestorTasques.java Java 
import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;
import java.util.ArrayList;
import java.util.List;

public class GestorTasques {

    private static final Path FITXER = Path.of("tasques.txt");

    // CREATE: afegeix una tasca al final, sense tocar la resta
    static void afegir(String tasca) throws IOException {
        try (BufferedWriter bw = Files.newBufferedWriter(FITXER, StandardCharsets.UTF_8,
                StandardOpenOption.CREATE, StandardOpenOption.APPEND)) {
            bw.write(tasca);
            bw.newLine();                       // salt de línia del sistema
        }
    }

    // READ: retorna totes les tasques, llegint línia a línia
    static List<String> llistar() throws IOException {
        List<String> tasques = new ArrayList<>();
        try (BufferedReader br = Files.newBufferedReader(FITXER, StandardCharsets.UTF_8)) {
            String linia;
            while ((linia = br.readLine()) != null) {   // null = final del fitxer
                tasques.add(linia);
            }
        }
        return tasques;
    }

    // Auxiliar: reescriu tot el fitxer amb el contingut de la llista
    private static void reescriure(List<String> tasques) throws IOException {
        // Sense opcions: CREATE + TRUNCATE_EXISTING + WRITE (esborra el contingut anterior)
        try (BufferedWriter bw = Files.newBufferedWriter(FITXER, StandardCharsets.UTF_8)) {
            for (String t : tasques) {
                bw.write(t);
                bw.newLine();
            }
        }
    }

    // UPDATE: canvia el text de la tasca que és a la posició indicada
    static void modificar(int posicio, String nouText) throws IOException {
        List<String> tasques = llistar();       // 1. llegir-ho tot (ja és un ArrayList modificable)
        tasques.set(posicio, nouText);          // 2. canviar la línia a la memòria
        reescriure(tasques);                    // 3. reescriure tot el fitxer
    }

    // DELETE: elimina les tasques amb aquest text
    static void esborrar(String tasca) throws IOException {
        List<String> tasques = llistar();       // 1. llegir-ho tot
        tasques.removeIf(t -> t.equals(tasca)); // 2. treure les línies que coincideixen
        reescriure(tasques);                    // 3. reescriure tot el fitxer
    }

    public static void main(String[] args) throws IOException {
        Files.deleteIfExists(FITXER);

        afegir("Comprar pa");
        afegir("Estudiar NIO.2");
        afegir("Enviar la pràctica");
        System.out.println(llistar());          // [Comprar pa, Estudiar NIO.2, Enviar la pràctica]

        modificar(1, "Estudiar fitxers de text");
        esborrar("Comprar pa");
        System.out.println(llistar());          // [Estudiar fitxers de text, Enviar la pràctica]
    }
}

Compte

Modificar i esborrar reescriuen el fitxer sencer encara que només canviï una línia. Amb fitxers grans és lent, i si dos programes ho fan alhora, un pot perdre els canvis de l'altre. Són alguns dels motius per fer servir una base de dades (RA2).

Nota

L'accés aleatori (apartat 7) permet modificar un registre sense reescriure el fitxer, però només quan tots els registres tenen la mateixa mida.

6. Serialització

La serialització és el procés que converteix un objecte en una seqüència de bytes per desar-lo en un fitxer o transmetre'l per una xarxa. La deserialització és el procés invers: reconstrueix l'objecte a partir d'aquests bytes.

Per entendre'n el funcionament, imaginem una classe anomenada Tasques:

Tasques.java Java 
import java.io.Serializable;
import java.time.LocalDate;

public class Tasques implements Serializable {

    private static final long serialVersionUID = 1L;

    private int id;
    private String titol;
    private LocalDate dataLimit;
    private boolean completada;

    public Tasques(int id, String titol, LocalDate dataLimit, boolean completada) {
        this.id = id;
        this.titol = titol;
        this.dataLimit = dataLimit;
        this.completada = completada;
    }

    public int getId() {
        return id;
    }

    public void setId(int id) {
        this.id = id;
    }

    public String getTitol() {
        return titol;
    }

    public void setTitol(String titol) {
        this.titol = titol;
    }

    public LocalDate getDataLimit() {
        return dataLimit;
    }

    public void setDataLimit(LocalDate dataLimit) {
        this.dataLimit = dataLimit;
    }

    public boolean isCompletada() {
        return completada;
    }

    public void setCompletada(boolean completada) {
        this.completada = completada;
    }

    @Override
    public String toString() {
        return "Tasques{id=" + id
                + ", titol='" + titol + '\''
                + ", dataLimit=" + dataLimit
                + ", completada=" + completada + '}';
    }
}

Fixeu-vos que Tasques ha estat definida com un POJO (Plain Old Java Object). Un POJO és una classe simple que conté, fonamentalment, els atributs, els constructors i els getters i setters. No té lògica de negoci ni mètodes que facin servir aquests atributs per produir un resultat (per exemple, convertir el títol a majúscules o validar dates a partir de la data límit).

D'altra banda, la classe implementa la interfície Serializable. És una interfície sense mètodes que només marca la classe com a serialitzable: sense ella, writeObject() llança NotSerializableException.

A partir d'aquí, vegem com es serialitza un objecte de la classe Tasques:

SerialitzarTasca.java Java 
import java.io.IOException;
import java.io.ObjectOutputStream;
import java.nio.file.Files;
import java.nio.file.Path;
import java.time.LocalDate;

public class SerialitzarTasca {
    public static void main(String[] args) {
        Path fitxer = Path.of("tasca.dat");

        Tasques original = new Tasques(1, "Corregir pràctiques", LocalDate.of(2026, 10, 15), false);

        try (ObjectOutputStream oos = new ObjectOutputStream(Files.newOutputStream(fitxer))) {
            oos.writeObject(original);
            System.out.println("Serialitzat: " + original);
        } catch (IOException e) {
            System.out.println("Error en serialitzar: " + e.getMessage());
        }
    }
}

El resultat és un fitxer binari que no es pot llegir com un fitxer de text pla. Tampoc no és l'objectiu: el fitxer està pensat per ser llegit per un programa Java, no per una persona.

De manera anàloga, la deserialització fa el procés invers i reconstrueix l'objecte de la classe a partir del fitxer:

DeserialitzarTasca.java Java 
import java.io.IOException;
import java.io.ObjectInputStream;
import java.nio.file.Files;
import java.nio.file.Path;

public class DeserialitzarTasca {

    public static void main(String[] args) {
        Path fitxer = Path.of("tasca.dat");

        try (ObjectInputStream ois = new ObjectInputStream(Files.newInputStream(fitxer))) {
            Tasques recuperada = (Tasques) ois.readObject();
            System.out.println("Deserialitzat: " + recuperada);
        } catch (IOException e) {
            System.out.println("Error en deserialitzar: " + e.getMessage());
        } catch (ClassNotFoundException e) {
            System.out.println("Classe no trobada: " + e.getMessage());
        }
    }
}

De la mateixa manera que es serialitza un objecte, també es poden serialitzar col·leccions d'objectes, com ara llistes (ArrayList) o mapes (HashMap).

Entre els avantatges de la serialització hi ha:

  • Desar i recuperar objectes sencers amb una sola instrucció.
  • Es conserva l'estructura completa dels objectes, incloses les referències entre ells.
  • No cal definir cap format de text (separadors de CSV, comes decimals, etc.) ni escriure codi per interpretar-lo.
  • Permet persistència senzilla i enviament per xarxa. És una manera ràpida de guardar l'estat d'un programa entre execucions, o d'enviar objectes per un socket entre dues aplicacions Java.
  • Amb serialVersionUID es controla la compatibilitat entre versions de la classe, fet que reforça el control sobre el que es guarda.

També té inconvenients:

  • El format és propi de Java: un programa escrit en un altre llenguatge no el pot llegir.
  • El fitxer no és llegible per una persona.
  • Deserialitzar dades de fonts desconegudes comporta riscos de seguretat.

Nota

ObjectOutputStream és la serialització nativa de Java, però no l'única. Els objectes també es poden serialitzar en formats de text com JSON o XML, que són llegibles i independents del llenguatge (unitat 05).
