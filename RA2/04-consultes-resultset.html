Consultes i resultats

Com s'executen consultes, com es recorre el ResultSet, com es guarden els resultats en objectes Java i com es consulten les metadades d'un resultat.

Què aprendràs

En acabar aquesta unitat has de ser capaç de:

  • Convertir files en objectes i retornar-los en una List o un Optional.
  • Consultar les columnes d'un resultat amb ResultSetMetaData.

1. executeQuery i el ResultSet

Les consultes SELECT s'executen amb executeQuery, que retorna un objecte ResultSet.

Definició

Un ResultSet és l'objecte que conté les files retornades per una consulta. Funciona com un cursor: en cada moment apunta a una sola fila, i només es poden llegir les columnes d'aquesta fila.

Inicialment el cursor es troba abans de la primera fila. Cada crida a next() l'avança una posició i retorna true si hi ha fila, o false si ja no en queden.

Per això el recorregut sempre té la mateixa forma:

Java Java 
String sql = "SELECT id, nom, ciutat FROM clients ORDER BY nom";

try (Connection con = ConnexioBD.obtenir();
     Statement st = con.createStatement();
     ResultSet rs = st.executeQuery(sql)) {

    while (rs.next()) {                        // avança i comprova si hi ha fila
        int id = rs.getInt("id");
        String nom = rs.getString("nom");
        String ciutat = rs.getString("ciutat");
        System.out.printf("%3d  %-20s %s%n", id, nom, ciutat);
    }
}

Si la consulta només pot retornar una fila (per exemple, per clau primària) n'hi ha prou amb un if:

Java Java 
try (ResultSet rs = st.executeQuery("SELECT COUNT(*) FROM clients")) {
    if (rs.next()) {
        System.out.println("Total de clients: " + rs.getInt(1));
    }
}

2. Llegir les columnes

2.1 Per nom o per posició

Cada mètode getXxx es pot cridar amb el nom de la columna o amb la seva posició (començant per 1):

Java Java 
rs.getString("nom");   // per nom: més llegible i resistent a canvis d'ordre al SELECT
rs.getString(2);       // per posició: útil per a columnes calculades sense nom

Nota

per a les columnes calculades és millor donar-los un nom amb AS i llegir-les per nom: SELECT COUNT(*) AS total ... i després rs.getInt("total").

2.2 Mètodes getXxx

2.3 Els valors NULL

Els mètodes que retornen tipus de referència (getString, getBigDecimal, getObject) retornen null quan la columna és NULL. Però els que retornen tipus primitius no poden retornar null: getInt retorna 0 i getBoolean retorna false.

Com es distingeix un 0 real d'un NULL? Hi ha dues maneres:

Java Java 
// Opció 1: wasNull() indica si l'última columna llegida era NULL
int quantitat = rs.getInt("quantitat");
if (rs.wasNull()) {
    System.out.println("Sense quantitat");
}

// Opció 2 (més clara): demanar un Integer, que sí pot ser null
Integer quantitat2 = rs.getObject("quantitat", Integer.class);

Per a les dates, getObject(..., LocalDate.class) també retorna null si la columna és NULL. A la botiga passa amb data_lliurament dels encàrrecs encara no lliurats.

3. Objectes per guardar el resultat

El ResultSet només és vàlid mentre la connexió és oberta: en sortir del try-with-resources es tanca i les seves dades ja no es poden llegir. Per això les dades s'han de copiar a objectes Java propis abans de tancar.

Compte

un mètode no ha de retornar mai un ResultSet. Quan el codi que el rebi el vulgui llegir, ja estarà tancat (o, pitjor, la connexió quedarà oberta indefinidament).

3.1 Una classe per cada tipus de fila

La manera més senzilla de definir l'objecte que guarda una fila és un record (Java 16): una classe immutable amb constructor, getters, equals, hashCode i toString generats automàticament.

Client.java Java 
import java.math.BigDecimal;
import java.time.LocalDate;

public record Client(int id, String nom, String email, String ciutat) { }

public record Article(int id, String nom, BigDecimal preu, int estoc) { }

public record Encarrec(int id, int idClient, LocalDate dataEncarrec, LocalDate dataLliurament) { }

Cada component del record correspon a una columna, amb el tipus Java de la taula de l'apartat 2.2. Aquesta és la traducció del desfasament objecte-relacional (unitat 08) que fem a mà amb JDBC.

3.2 De fila a objecte

Convé tenir un mètode que converteixi la fila actual del ResultSet en un objecte. Així la conversió s'escriu una sola vegada:

Java Java 
private static Client mapejarClient(ResultSet rs) throws SQLException {
    return new Client(
            rs.getInt("id"),
            rs.getString("nom"),
            rs.getString("email"),
            rs.getString("ciutat"));          // pot ser null
}

3.3 Moltes files: una List

Java Java 
public static List<Client> llistarClients() throws SQLException {
    String sql = "SELECT id, nom, email, ciutat FROM clients ORDER BY nom";
    List<Client> clients = new ArrayList<>();

    try (Connection con = ConnexioBD.obtenir();
         Statement st = con.createStatement();
         ResultSet rs = st.executeQuery(sql)) {

        while (rs.next()) {
            clients.add(mapejarClient(rs));
        }
    }
    return clients;          // la connexió ja és tancada; la llista continua sent vàlida
}

3.4 Una fila o cap: un Optional

Buscar per clau primària pot retornar un client o cap. En lloc de retornar null, és més clar retornar un Optional:

Java Java 
public static Optional<Client> buscarClient(int id) throws SQLException {
    String sql = "SELECT id, nom, email, ciutat FROM clients WHERE id = ?";

    try (Connection con = ConnexioBD.obtenir();
         PreparedStatement ps = con.prepareStatement(sql)) {

        ps.setInt(1, id);
        try (ResultSet rs = ps.executeQuery()) {
            return rs.next() ? Optional.of(mapejarClient(rs)) : Optional.empty();
        }
    }
}

// Ús:
buscarClient(3).ifPresentOrElse(
        c -> System.out.println("Trobat: " + c.nom()),
        () -> System.out.println("No existeix cap client amb aquest id"));

4. Consultes amb paràmetres

Igual que a la unitat 03, qualsevol valor que vingui de fora s'ha de passar amb PreparedStatement:

Java Java 
public static List<Article> buscarArticles(String text, BigDecimal preuMaxim) throws SQLException {
    String sql = """
            SELECT id, nom, preu, estoc
            FROM articles
            WHERE LOWER(nom) LIKE ? AND preu <= ?
            ORDER BY preu""";
    List<Article> resultat = new ArrayList<>();

    try (Connection con = ConnexioBD.obtenir();
         PreparedStatement ps = con.prepareStatement(sql)) {

        ps.setString(1, "%" + text.toLowerCase() + "%");    // els % van al valor, no a l'SQL
        ps.setBigDecimal(2, preuMaxim);

        try (ResultSet rs = ps.executeQuery()) {
            while (rs.next()) {
                resultat.add(new Article(
                        rs.getInt("id"),
                        rs.getString("nom"),
                        rs.getBigDecimal("preu"),
                        rs.getInt("estoc")));
            }
        }
    }
    return resultat;
}

Compte

el comodí % del LIKE s'afegeix al valor del paràmetre. Escriure LIKE '%?%' a l'SQL no funciona: dins de les cometes, el ? és un caràcter literal i no un paràmetre.

5. ResultSetMetaData

ResultSetMetaData dona informació sobre les columnes d'un resultat: quantes n'hi ha, com es diuen i de quin tipus són. S'obté amb rs.getMetaData().

És útil quan el programa no sap per endavant quines columnes tindrà la consulta. Per exemple, aquest mètode mostra en forma de taula el resultat de qualsevol SELECT:

Java Java 
public static void mostrarTaula(String sql) throws SQLException {
    try (Connection con = ConnexioBD.obtenir();
         Statement st = con.createStatement();
         ResultSet rs = st.executeQuery(sql)) {

        ResultSetMetaData md = rs.getMetaData();
        int numColumnes = md.getColumnCount();

        // Capçalera: nom de cada columna
        for (int i = 1; i <= numColumnes; i++) {
            System.out.printf("%-18s", md.getColumnLabel(i));
        }
        System.out.println();
        System.out.println("-".repeat(18 * numColumnes));

        // Files: getObject serveix per a qualsevol tipus
        while (rs.next()) {
            for (int i = 1; i <= numColumnes; i++) {
                System.out.printf("%-18s", rs.getObject(i));
            }
            System.out.println();
        }
    }
}

// Ús:
mostrarTaula("SELECT nom, preu, estoc FROM articles WHERE estoc < 5");
MètodeRetorna
getColumnCount()Nombre de columnes
getColumnLabel(i)Nom de la columna, o el seu àlies si en té
getColumnTypeName(i)Tipus al SGBD (varchar, numeric, int4...)
isNullable(i)Si la columna admet NULL

Nota

fes servir getColumnLabel i no getColumnName: el primer retorna l'àlies de l'AS, que és el nom que veu l'usuari.
