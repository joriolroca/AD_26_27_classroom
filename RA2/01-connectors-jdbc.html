1. Què és un connector

Quan desenvolupem una aplicació Java que accedeix a una base de dades, hem de tenir en compte que cada SGBD es comunica amb els clients amb el seu propi protocol: la manera com PostgreSQL rep una consulta i retorna les files és diferent de com ho fan MySQL, Oracle o SQL Server.

Si l'aplicació hagués de parlar directament amb el SGBD, hauríem d'implementar aquest protocol nosaltres mateixos i, en canviar de base de dades, hauríem de reescriure tota la part d'accés a dades.

Definició

Un connector (o driver) és una biblioteca que implementa una interfície estàndard d'accés a dades i tradueix les crides de l'aplicació al protocol concret d'un SGBD. En Java, aquesta interfície estàndard és JDBC.

Per connectar la nostra aplicació amb una base de dades necessitem, doncs, el connector del SGBD que fem servir. L'aplicació només coneix la interfície estàndard; per canviar de SGBD, en principi, n'hi ha prou amb canviar el driver i l'adreça de connexió.

Compte

el driver amaga les diferències de protocol, però no les del dialecte SQL. Si les consultes fan servir sintaxi pròpia d'un SGBD (LIMIT, TOP, SERIAL, AUTO_INCREMENT, funcions de dates...), també caldrà adaptar-les.

2. L'arquitectura de JDBC

JDBC té dues parts:

  • L'API JDBC: les interfícies i classes que fa servir el programador. Estan als paquets java.sql (el nucli) i javax.sql (funcions avançades com DataSource i el pooling de connexions).
  • Els drivers JDBC: les implementacions d'aquestes interfícies per a cada SGBD. Normalment els proporciona el fabricant del SGBD o la comunitat del projecte.

Per obtenir una connexió hi ha dues vies:

  • DriverManager: rep l'URL de connexió i la passa al driver que la reconeix. Els drivers es registren automàticament si són al classpath (des de Java 6 no cal Class.forName).
  • DataSource: l'alternativa recomanada en aplicacions reals, perquè permet configurar la connexió fora del codi i fer servir pools de connexions.

Un cop obtinguda la Connection, el programa treballa directament amb els objectes del driver.

3. Arquitectures de dues i tres capes

Dues capes. L'aplicació Java fa servir el driver per connectar-se directament al SGBD. És el model de moltes eines internes i aplicacions de gestió en xarxa local, i el de tots els exemples d'aquest RA. 

flowchart LR
    A["Aplicació Java<br/>+ driver JDBC"] -- "xarxa" --> B[("SGBD")]

Cas especial

amb bases de dades embegudes (SQLite, H2, Derby), el motor de la base de dades s'executa dins de la mateixa aplicació i no hi ha connexió de xarxa.

Tres capes. El client no es connecta a la base de dades. Envia peticions a un servidor intermedi (una API, un servidor d'aplicacions), i és aquest qui fa servir JDBC. 

flowchart LR
    A["Client<br/>web o mòbil"] -- "HTTP" --> B["Servidor d'aplicacions<br/>+ driver JDBC"] -- "xarxa" --> C[("SGBD")]

Per què les aplicacions web i mòbils no s'han de connectar directament al SGBD?

  • Les credencials de la base de dades només les coneix el servidor.
  • El SGBD no queda exposat a Internet.
  • La lògica de negoci i les validacions es controlen en un sol lloc.
  • El servidor pot reutilitzar connexions amb un pool, en lloc d'obrir-ne una per a cada client.

4. Afegir el driver amb Maven

En aquest mòdul farem servir Maven per gestionar les dependències, sense cap framework al damunt.

Maven és una eina de gestió i construcció de projectes Java de l'Apache Software Foundation. Dues de les seves funcionalitats més importants són:

  • Gestionar les dependències: es declaren al pom.xml i Maven les descarrega de Maven Central.
  • Imposar una estructura de projecte estàndard.

4.1 Instal·lació de Maven

Primer comprovem si Maven ja està instal·lat:

Terminal Terminal 
mvn -v

Si l'ordre no es reconeix, cal instal·lar-lo:

  1. Descarrega el Binary zip archive (apache-maven-3.9.x-bin.zip) de https://maven.apache.org/download.cgi.
  2. Descomprimeix-lo en una carpeta sense espais, per exemple C:\apache-maven-3.9.x.
  3. Crea la variable d'entorn JAVA_HOME amb la carpeta arrel del JDK (sense \bin), si no existeix.
  4. Afegeix a la variable Path la carpeta bin de Maven: C:\apache-maven-3.9.x\bin.
  5. Obre un terminal nou i torna a executar mvn -v.

Compte

JAVA_HOME apunta a l'arrel del JDK, mentre que al Path hi van carpetes bin. Les variables noves només les veuen els programes que s'obren després de crear-les, inclòs l'IDE.

4.2 Estructura del projecte

El projecte ha de seguir l'estructura estàndard de Maven:

Text Text 
demo/
├── pom.xml
└── src/
    └── main/
        ├── java/
        │   └── demo/
        │       └── App.java
        └── resources/
            └── conn.properties
  • src/main/java conté el codi font. Les carpetes que hi ha a sota corresponen al paquet: App.java ha de començar amb package demo;.
  • src/main/resources conté els fitxers de configuració. Maven els copia al classpath; és on va el conn.properties amb les dades de connexió (unitat 02).

4.3 El pom.xml

El pom.xml és el fitxer de configuració d'un projecte Maven: identifica el projecte, en declara les dependències i indica com s'ha de construir.

pom.xml XML 
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
                             http://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <groupId>demo</groupId>
    <artifactId>DEMO-RA2.1</artifactId>
    <version>1.0</version>

    <properties>
        <maven.compiler.release>21</maven.compiler.release>
        <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    </properties>

    <dependencies>
        <!-- Driver JDBC de PostgreSQL -->
        <dependency>
            <groupId>org.postgresql</groupId>
            <artifactId>postgresql</artifactId>
            <version>42.7.4</version>
        </dependency>
    </dependencies>
</project>

4.4 Compilar i executar

Cada vegada que es modifica el pom.xml cal recarregar el projecte a l'IDE (a VS Code, clic dret sobre el pom.xml > Reload project).
