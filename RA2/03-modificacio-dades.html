Modificar el contingut de la base de dades

Com s'insereixen, es modifiquen i s'esborren dades des de Java amb Statement i PreparedStatement, com es recupera la clau generada i com es tracten els errors d'integritat.

DAM RA2 Modificar dades

Criteris d'avaluació relacionats

  • 2.6 Desenvolupa aplicacions que modifiquen el contingut de la base de dades.
  • 2.9 Elimina els objectes un cop finalitzada la funció.

Què aprendràs

En acabar aquesta unitat has de ser capaç de:

  • Inserir, modificar i esborrar files des de Java.
  • Explicar què és la injecció SQL i per què Statement no és segur amb dades de l'usuari.
  • Fer servir PreparedStatement i els seus mètodes setXxx.
  • Recuperar la clau generada pel SGBD després d'un INSERT.
  • Tractar els errors d'integritat que retorna el SGBD.

1. DDL i DML

Les sentències SQL es classifiquen segons què fan:

TipusNomSentènciesUnitat
DDLData Definition LanguageCREATE, ALTER, DROP, TRUNCATE09
DMLData Manipulation LanguageINSERT, UPDATE, DELETE03
DQLData Query LanguageSELECT04
TCLTransaction Control LanguageCOMMIT, ROLLBACK, SAVEPOINT05

Les sentències DDL defineixen l'estructura: quines taules hi ha, quines columnes tenen i quines restriccions s'apliquen. Normalment s'executen una vegada, en instal·lar l'aplicació o quan canvia la versió.

2. La interfície Statement

Un Statement s'obté a partir de la connexió i serveix per executar sentències SQL fixes, sense paràmetres. Té tres mètodes d'execució:

MètodeRetornaS'utilitza per a
executeQuery(sql)ResultSetSELECT
executeUpdate(sql)int: files afectades (0 per a DDL)INSERT, UPDATE, DELETE i DDL
execute(sql)boolean: true si el resultat és un ResultSetQualsevol sentència, quan no se sap de quin tipus és

Tots els exemples parteixen del mètode obtenir() de la classe ConnexioBD, descrita a la unitat 02:

ConnexioBD.java Java 
import java.io.BufferedReader;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.SQLException;
import java.util.Properties;

public final class ConnexioBD {

    private static final Path FITXER_CONFIG =
            Path.of("src", "main", "resources", "conn.properties");

    private static final Properties CONFIG = carregarConfiguracio();

    private ConnexioBD() {
        // Classe d'utilitat: no s'instancia
    }

    private static Properties carregarConfiguracio() {
        Properties p = new Properties();
        // El lector es declara al try-with-resources perquè es tanqui sol
        try (BufferedReader lector = Files.newBufferedReader(FITXER_CONFIG)) {
            p.load(lector);
        } catch (IOException e) {
            throw new IllegalStateException("No s'ha pogut llegir " + FITXER_CONFIG.toAbsolutePath(), e);
        }
        return p;
    }

    /** Retorna una connexió nova. Qui la demana és responsable de tancar-la. */
    public static Connection obtenir() throws SQLException {
        return DriverManager.getConnection(
                CONFIG.getProperty("db.url"),
                CONFIG.getProperty("db.usuari"),
                CONFIG.getProperty("db.contrasenya"));
    }
}

3. executeUpdate

Les sentències DML (INSERT, UPDATE, DELETE) s'executen amb executeUpdate, que retorna el nombre de files afectades:

Java Java 
try (Connection con = ConnexioBD.obtenir();
     Statement st = con.createStatement()) {

    int files = st.executeUpdate(
            "INSERT INTO articles (nom, preu, estoc) VALUES ('Teclat', 24.90, 10)");
    System.out.println("Files inserides: " + files);      // 1
}

El valor de retorn és important: un UPDATE o un DELETE que retorna 0 vol dir que cap fila complia la condició del WHERE, i normalment l'aplicació ho ha de comunicar a l'usuari.

4. El problema de concatenar: injecció SQL

L'exemple anterior té els valors escrits al codi. En una aplicació real els valors vénen de l'usuari, i la temptació és construir la sentència concatenant:

Java Java 
// MALAMENT: el valor de l'usuari es concatena dins de l'SQL
public static void esborrarClient(String email) throws SQLException {
    String sql = "DELETE FROM clients WHERE email = '" + email + "'";
    try (Connection con = ConnexioBD.obtenir();
         Statement st = con.createStatement()) {
        st.executeUpdate(sql);
    }
}

Amb un email normal, la sentència resultant és la que esperem:

SQL SQL 
DELETE FROM clients WHERE email = 'pau@exemple.cat'

Però si l'usuari escriu x' OR '1'='1, la sentència queda així:

SQL SQL 
DELETE FROM clients WHERE email = 'x' OR '1'='1'

La condició '1'='1' és sempre certa: s'esborren tots els clients.

Definició

La injecció SQL és un atac que consisteix a introduir fragments d'SQL en una dada d'entrada perquè, en concatenar-la, alterin la sentència que executa l'aplicació. Permet llegir, modificar o esborrar dades sense autorització.

A més del problema de seguretat, concatenar també falla amb dades perfectament legítimes: un client que es digui O'Brien trenca la sentència per culpa de l'apòstrof.

5. PreparedStatement

PreparedStatement és una subinterfície de Statement que treballa amb sentències precompilades amb paràmetres. Cada valor variable es marca amb un ? i s'assigna després amb un mètode setXxx:

Java Java 
// BÉ: el valor viatja separat de l'SQL
public static int esborrarClient(String email) throws SQLException {
    String sql = "DELETE FROM clients WHERE email = ?";

    try (Connection con = ConnexioBD.obtenir();
         PreparedStatement ps = con.prepareStatement(sql)) {

        ps.setString(1, email);          // el primer ? és el número 1
        return ps.executeUpdate();
    }
}

Ara, si l'usuari escriu x' OR '1'='1, el SGBD busca un client amb aquest email literal, no en troba cap i no esborra res.

Avantatges de PreparedStatement

  • Seguretat: impossibilita la injecció SQL.
  • Correcció: el driver s'encarrega dels apòstrofs, els decimals, les dates i els NULL.
  • Rendiment: si es reutilitza amb valors diferents, el SGBD no ha de tornar a analitzar la sentència.
  • Llegibilitat: l'SQL es llegeix sencer, sense cometes i + pel mig.

Recorda

a partir d'ara, qualsevol sentència amb valors que no siguin constants del programa es fa amb PreparedStatement.

5.1 Mètodes setXxx

Tipus SQLTipus JavaMètode
INTEGERintsetInt(i, valor)
BIGINTlongsetLong(i, valor)
NUMERIC(p,s)BigDecimalsetBigDecimal(i, valor)
DOUBLE PRECISIONdoublesetDouble(i, valor)
VARCHAR, TEXTStringsetString(i, valor)
BOOLEANbooleansetBoolean(i, valor)
DATELocalDatesetObject(i, valor)
TIMESTAMPLocalDateTimesetObject(i, valor)
Qualsevol, a NULLsetNull(i, Types.XXX)

Compte

per a imports i preus fes servir sempre BigDecimal i NUMERIC, mai double. Els double no poden representar exactament valors com 0.1 i acumulen errors d'arrodoniment.

Nota

les dates de java.time (LocalDate, LocalDateTime) es passen amb setObject des de JDBC 4.2. Les classes antigues java.sql.Date i java.sql.Timestamp encara funcionen, però no cal fer-les servir.

6. INSERT i claus generades

6.1 Inserir una fila

Java Java 
public static void inserirArticle(String nom, BigDecimal preu, int estoc) throws SQLException {
    String sql = "INSERT INTO articles (nom, preu, estoc) VALUES (?, ?, ?)";

    try (Connection con = ConnexioBD.obtenir();
         PreparedStatement ps = con.prepareStatement(sql)) {

        ps.setString(1, nom);
        ps.setBigDecimal(2, preu);
        ps.setInt(3, estoc);
        ps.executeUpdate();
    }
}

// Ús:
inserirArticle("Ratolí sense fil", new BigDecimal("19.95"), 25);

6.2 Valors NULL

La columna ciutat de clients admet NULL. Si l'usuari no l'indica, s'ha d'inserir un NULL, no una cadena buida:

if (ciutat == null || ciutat.isBlank()) {
    ps.setNull(3, Types.VARCHAR);
} else {
    ps.setString(3, ciutat);
}

6.3 Recuperar l'id generat

Les taules de la botiga tenen l'id generat pel SGBD (GENERATED ALWAYS AS IDENTITY). Moltes vegades, just després d'inserir, el programa necessita saber quin id s'ha assignat; per exemple, per inserir les línies d'un encàrrec que s'acaba de crear.

Per obtenir-lo s'indica en preparar la sentència quines columnes generades es volen recuperar, i després es llegeixen amb getGeneratedKeys():

Java Java 
public static int inserirClient(String nom, String email, String ciutat) throws SQLException {
    String sql = "INSERT INTO clients (nom, email, ciutat) VALUES (?, ?, ?)";

    try (Connection con = ConnexioBD.obtenir();
         PreparedStatement ps = con.prepareStatement(sql, new String[] { "id" })) {

        ps.setString(1, nom);
        ps.setString(2, email);
        if (ciutat == null) {
            ps.setNull(3, Types.VARCHAR);
        } else {
            ps.setString(3, ciutat);
        }
        ps.executeUpdate();

        // getGeneratedKeys retorna un ResultSet amb una fila per cada fila inserida
        try (ResultSet claus = ps.getGeneratedKeys()) {
            if (claus.next()) {
                return claus.getInt(1);
            }
            throw new SQLException("No s'ha retornat cap id");
        }
    }
}

Nota

també existeix la forma prepareStatement(sql, Statement.RETURN_GENERATED_KEYS). Funciona, però amb PostgreSQL retorna totes les columnes de la fila inserida. Indicar el nom de la columna (new String[] { "id" }) és més precís i funciona igual a H2 i a PostgreSQL.

7. UPDATE i DELETE

7.1 Modificar

Java Java 
public static boolean actualitzarPreu(int idArticle, BigDecimal preuNou) throws SQLException {
    String sql = "UPDATE articles SET preu = ? WHERE id = ?";

    try (Connection con = ConnexioBD.obtenir();
         PreparedStatement ps = con.prepareStatement(sql)) {

        ps.setBigDecimal(1, preuNou);
        ps.setInt(2, idArticle);
        return ps.executeUpdate() == 1;          // false si l'article no existeix
    }
}

Un UPDATE pot afectar moltes files. Per exemple, apujar un percentatge tots els articles amb poc estoc:

Java Java 
String sql = "UPDATE articles SET preu = ROUND(preu * (1 + ? / 100.0), 2) WHERE estoc < ?";

try (Connection con = ConnexioBD.obtenir();
     PreparedStatement ps = con.prepareStatement(sql)) {

    ps.setBigDecimal(1, new BigDecimal("5"));   // +5 %
    ps.setInt(2, 3);                            // articles amb menys de 3 unitats
    int files = ps.executeUpdate();
    System.out.println(files + " articles actualitzats");
}

7.2 Esborrar

Java Java 
public static boolean esborrarArticle(int idArticle) throws SQLException {
    String sql = "DELETE FROM articles WHERE id = ?";

    try (Connection con = ConnexioBD.obtenir();
         PreparedStatement ps = con.prepareStatement(sql)) {

        ps.setInt(1, idArticle);
        return ps.executeUpdate() > 0;
    }
}

Compte

un UPDATE o un DELETE sense WHERE afecta totes les files de la taula. Revisa sempre la condició abans d'executar-los.

8. Errors d'integritat

Les restriccions de l'esquema (unitat 09) les comprova el SGBD. Quan una sentència les incompleix, el driver llança una SQLException amb un SQLState de la classe 23:

SQLStateRestriccióExemple a la botiga
23505UNIQUE o PRIMARY KEYInserir un client amb un email que ja existeix
23503FOREIGN KEYEsborrar un article que apareix en alguna línia d'encàrrec
23502NOT NULLInserir un article sense nom
23514CHECKPosar un preu negatiu

L'aplicació no ha de mostrar a l'usuari el missatge tècnic del SGBD, sinó interpretar-lo.
