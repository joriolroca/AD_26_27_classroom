1. Què és una transacció

Crear un encàrrec a la botiga no és una sola operació. Cal:

  1. Inserir l'encàrrec a encarrecs.
  2. Inserir cada línia a linies_encarrec.
  3. Descomptar l'estoc de cada article a articles.

Si el programa falla després del pas 2 (per exemple, perquè un article no té prou estoc), la base de dades queda inconsistent: un encàrrec registrat amb un estoc que no s'ha descomptat.

Definició

Una transacció és un conjunt d'operacions sobre la base de dades que s'executen com una unitat: o s'apliquen totes, o no se n'aplica cap.

Les transaccions compleixen les propietats ACID:

PropietatSignificatA la botiga
Atomicitat (Atomicity)Tot o resNo pot quedar un encàrrec sense les seves línies
Consistència (Consistency)La base de dades passa d'un estat vàlid a un altre estat vàlidL'estoc mai queda negatiu (CHECK)
Aïllament (Isolation)Les transaccions simultànies no s'interfereixenDos clients que compren alhora no es trepitgen
Durabilitat (Durability)Un cop confirmada, la transacció es manté encara que caigui el sistemaUn encàrrec confirmat no es perd per un tall de llum

Una transacció acaba de dues maneres:

  • COMMIT: es confirmen tots els canvis i passen a ser definitius i visibles per a tothom.
  • ROLLBACK: es desfan tots els canvis fets des de l'inici de la transacció.

2. El mode autocommit

Per defecte, una connexió JDBC treballa en mode autocommit: cada sentència és una transacció per si mateixa i, si s'executa correctament, el driver fa un COMMIT automàticament.

És el que ha passat a totes les unitats anteriors sense que ho haguem notat. Per a operacions d'una sola sentència és el comportament correcte. Però quan diverses sentències han d'anar juntes, cal desactivar-lo:

Mètode de ConnectionQuè fa
setAutoCommit(false)Desactiva l'autocommit: la transacció continua oberta fins que es crida commit() o rollback()
getAutoCommit()Indica si l'autocommit està activat
commit()Confirma la transacció actual
rollback()Desfà la transacció actual

Compte

si es desactiva l'autocommit i es tanca la connexió sense fer commit(), el comportament depèn del driver. PostgreSQL i H2 fan rollback, però no t'hi refiïs: acaba sempre explícitament amb commit() o rollback().

3. Commit i rollback

3.1 Incorrecte: l'error es perd

Java Java 
// MALAMENT
con.setAutoCommit(false);
try (PreparedStatement ps = con.prepareStatement(sql)) {
    ps.setInt(1, quantitat);
    ps.setInt(2, idArticle);
    ps.executeUpdate();
    con.commit();
} catch (SQLException e) {
    con.rollback();          // es desfà, però ningú se n'assabenta
}

Aquest codi té dos problemes:

  • L'excepció es perd: qui ha cridat el mètode creu que tot ha anat bé.
  • Si rollback() també falla (per exemple, perquè la connexió s'ha tallat), aquesta nova excepció amaga la primera.

3.2 Correcte: el patró de transacció

Java Java 
// BÉ
public static void operacioTransaccional() throws SQLException {
    try (Connection con = ConnexioBD.obtenir()) {
        con.setAutoCommit(false);                    // 1. comença la transacció

        try {
            // 2. totes les sentències fan servir la mateixa connexió
            // ...
            con.commit();                            // 3a. tot ha anat bé: confirma

        } catch (SQLException e) {
            con.rollback();                          // 3b. alguna cosa ha fallat: desfà
            throw e;                                 //     i avisa qui ha cridat el mètode
        }
    }                                                // 4. la connexió es tanca sempre
}

Les claus del patró:

  • Totes les sentències de la transacció han d'anar per la mateixa connexió. Una transacció pertany a una connexió: si una sentència obté una connexió nova amb ConnexioBD.obtenir(), queda fora de la transacció.
  • El rollback() es fa al catch i després es torna a llançar l'excepció.
  • La connexió es tanca amb el try-with-resources exterior, tant si ha anat bé com si no.

Nota

si la connexió prové d'un pool (unitat 02), abans de retornar-la s'ha de deixar l'autocommit com estava (con.setAutoCommit(true)), perquè la següent operació que la rebi no es trobi una connexió en mode transacció. Amb DriverManager no cal, perquè la connexió es destrueix en tancar-la.

4. Un cas complet: crear un encàrrec

Apliquem el patró al cas de l'apartat 1. Cada línia de l'encàrrec es representa amb un record:

LiniaNova.java Java 
public record LiniaNova(int idArticle, int quantitat) { }
Java Java 
public static int crearEncarrec(int idClient, List<LiniaNova> linies) throws SQLException {
    String sqlEncarrec = "INSERT INTO encarrecs (id_client) VALUES (?)";
    String sqlEstoc = """
            UPDATE articles SET estoc = estoc - ?
            WHERE id = ? AND estoc >= ?""";
    String sqlLinia = """
            INSERT INTO linies_encarrec (id_encarrec, id_article, quantitat, preu_unitari)
            SELECT ?, id, ?, preu FROM articles WHERE id = ?""";

    try (Connection con = ConnexioBD.obtenir()) {
        con.setAutoCommit(false);

        try (PreparedStatement psEnc = con.prepareStatement(sqlEncarrec, new String[] { "id" });
             PreparedStatement psEstoc = con.prepareStatement(sqlEstoc);
             PreparedStatement psLinia = con.prepareStatement(sqlLinia)) {

            // 1. Encàrrec
            psEnc.setInt(1, idClient);
            psEnc.executeUpdate();
            int idEncarrec;
            try (ResultSet claus = psEnc.getGeneratedKeys()) {
                claus.next();
                idEncarrec = claus.getInt(1);
            }

            for (LiniaNova l : linies) {
                // 2. Descomptar l'estoc, només si n'hi ha prou
                psEstoc.setInt(1, l.quantitat());
                psEstoc.setInt(2, l.idArticle());
                psEstoc.setInt(3, l.quantitat());
                if (psEstoc.executeUpdate() == 0) {
                    throw new SQLException("Estoc insuficient per a l'article " + l.idArticle());
                }

                // 3. Línia, amb el preu actual de l'article
                psLinia.setInt(1, idEncarrec);
                psLinia.setInt(2, l.quantitat());
                psLinia.setInt(3, l.idArticle());
                psLinia.executeUpdate();
            }

            con.commit();
            return idEncarrec;

        } catch (SQLException e) {
            con.rollback();       // ni encàrrec, ni línies, ni canvis d'estoc
            throw e;
        }
    }
}

Fixa't en el UPDATE ... WHERE id = ? AND estoc >= ?: si no hi ha prou estoc, no actualitza cap fila i executeUpdate retorna 0. Llavors el mateix programa llança l'excepció que provoca el rollback, i l'encàrrec que ja s'havia inserit també es desfà.

Recorda

el mateix patró és el que fa que un lot de sentències executat amb executeBatch() s'apliqui sencer o no s'apliqui gens: setAutoCommit(false), executeBatch(), commit() i rollback() al catch.

Nota

a PostgreSQL també les sentències DDL formen part de la transacció i es poden desfer amb rollback. A MySQL i Oracle, en canvi, un CREATE o un DROP fa un COMMIT implícit de tot el que hi havia pendent.
